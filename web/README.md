# 网页对战

从仓库根目录运行：

```sh
npm --prefix web/frontend run build
.venv/bin/python -m uvicorn web.backend.app:app --host 0.0.0.0 --port 8080
```

打开 http://localhost:8080/live ，同局域网可使用服务器的局域网地址和8080端口。
“当前 RL 模型”由 `configs/web/semantic_live.toml` 指定模型类型、训练规则配置、checkpoint、可选评估报告和推理参数。`n_simulations = 0` 使用策略网络直接决策，正数使用网络引导 MCTS；`max_rollout_depth` 限制搜索深度。网页与评估都通过 `training.core.matchup.loaders.load_player` 装载模型。Web 允许加载源码指纹不同的历史 checkpoint；只要文件位于 `artifacts/` 且模型格式与网络形状可加载，即可开始对局。评估报告不参与准入，仅当 checkpoint SHA、场景、源码指纹和 `player_spec` 都与当前部署一致时才展示评估指标。

队伍人数、角色池和双方是否允许重叠都来自 profile，profile 则读取服务选中的训练配置。每队编号1的角色先出战，P0/P1选择你控制的席位；牌组、骰子规则和回合上限也沿用同一训练配置。每回合双方先掷骰并依次完成一次重掷，随后结算回合开始效果并进入行动阶段。
棋盘按玩家视角展示：对手在上、自己在下（包括选择 P1 时）；支援区在左、召唤物区在右，骰子在最右。对手仅显示骰子总数和手牌数量，服务端也会隐藏明细。行动在棋盘右侧的决策栏中依次完成行动、目标、支付和确认；移动端使用底部决策面板。重掷、行动支付和元素调和都在棋盘中央的骰子选择界面完成：单击切换一枚骰子，按住并拖过多枚骰子可按起始状态连续选择或取消，也可临时收起选择界面查看当前局面。手牌拖到场上表示打出，拖到我方骰子区域表示元素调和；点击手牌仍可打开两种行动的选择入口。阵容设置与对局记录可折叠。

每场网页对战都会写入 `artifacts/web_live/sessions/<session_id>/web/`：`metadata.json` 保存建局配置，`events.jsonl` 记录建局、双方行动、每次状态推进、异常和结束原因，`replays/match.yaml` 在每步行动后持续更新。中途断开或重新开局也会保留截至当时的完整记录；在回放页刷新列表后即可打开对应 replay。

未安装兼容 RL 模型时，可手动选择“随机对手 · 练习体验”，使用同一 native profile 的规则和随机合法牌组试用界面；页面持续标注其为随机对手。这不代表当前 RL 模型实力。角色和卡牌插画使用仓库 `data/raw` 快照中的官方素材 URL，加载失败时回退为带名称的卡面；离线环境不保证插画可用。死亡后的替补选择使用实际等待输入的一方，不依赖行动权；对局记录显示双方行动。

仓库默认服务配置使用 `artifacts/exit_az/release/az_exit/` 部署槽位，checkpoint 不随源码安装，因此新 checkout 会显示模型不可用。规则关联输入改变后 checkpoint 格式为 `semantic-q/2.0.0`；旧 `1.0.0` 权重不能重标或复制进该槽位，必须用当前源码生成新的模型与匹配评估报告，再更新服务配置。旧引擎格式的历史回放不做跨规则兼容；回放回归测试使用当前引擎生成的记录。
