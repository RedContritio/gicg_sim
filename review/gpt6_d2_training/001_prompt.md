# D2 训练路线独立审查

请作为强化学习、AlphaZero / Expert Iteration、不完全信息博弈方面的独立研究审查者，评审下面的技术路线与训练计划。请主动质疑前提，不要默认现有路线正确，也不要只给泛泛建议。

## 项目与目标

这是一个类似原神七圣召唤的 3v3 卡牌环境。动作包括技能、出牌、切换、调和、骰子支付、选择目标、结束回合，以及每回合开始的骰子重掷。环境包含隐藏信息与随机骰子。

目标是在保持规则泛化能力的前提下，稳定战胜固定的 F1-D2 贪心基线。正式完成标准是多训练种子、独立测试 seed、双席位双布局、按场景聚类的 95% CI 下界高于 50%，同时 heldout 规则变体不明显退化。

## 当前技术路线

### 规则环境

1. 游戏规则由 Lua 子集 DSL 表达，包括角色、卡牌、伤害、治疗、能量、元素反应、状态和触发效果。
2. Go 引擎只负责通用 counter、hook、回合和动作执行，不在引擎中硬编码具体卡牌规则。
3. Python 通过 c-shared 接口驱动环境、采集轨迹和训练。
4. 目标是语义泛化，因此 observation 和网络输入不使用卡牌或角色 ID，而使用规则结构、counter、hook、费用、目标和效果属性。
5. 对手手牌、牌库顺序和对手骰子颜色属于隐藏信息；搜索采用 determinization / IS-MCTS 思路处理。

### 状态与动作表示

1. 网络接收两类主要信息：
   - 当前动态状态：角色状态、counter、骰子、手牌、回合信息等；
   - 静态规则信息：hook、操作序列、技能和卡牌的语义结构。
2. 网络不是在固定动作词表上分类，而是对当前环境枚举出的合法动作逐个打分。
3. 单个合法动作包含：
   - 动作类型；
   - 对应技能或卡牌的规则引用；
   - 目标；
   - 骰子支付组合；
   - 调和来源颜色；
   - 重掷颜色和数量。
4. 当前 `max_actions=2048`。不同支付方式会成为不同合法动作，因此动作空间在部分状态下较大。
5. 当前模型规模较小：`d_model=32`、1 层 cross interaction。选择小模型是为了低延迟和规则泛化，不希望依赖大规模 ID 记忆。

### 历史上最强的学习路线

目前最强策略并不是 AlphaZero，而是：

1. 先用 F1-D2 教师生成 executed-action imitation 数据；
2. 做行为克隆 warm-start；
3. 再使用 semantic DMC / Monte-Carlo RL，以完整终局结果更新动作价值；
4. 连续 16 轮 RL 后得到 RL16；
5. RL16 在旧环境中对 F1-D2 约 42%–45%，heldout 规则变体约 40%–43%。

该路线的推理方式是合法动作打分后直接 argmax。它没有可靠的独立 value head，但目前是最强的已确认策略。

### 当前 AZ / ExIt 路线

为了让搜索与学习联合提升，后来把 RL16 转换成 AZ 网络：

1. 复制兼容的语义编码器和 trunk；
2. 将 RL16 的 Q / action head 映射到 AZ policy head；
3. value head 和 delta auxiliary head 重新初始化；
4. 使用 MCTS visit distribution 训练 policy；
5. 使用终局 z 训练 value；
6. 使用状态变化训练 delta auxiliary head；
7. 可选使用冻结 RL16 policy 做 distillation anchor，防止强初始化迅速漂移。

此前 ExIt / AZ 的多个实验均没有超过 RL16，且经常严重退化。因此这次不是已经验证成功的扩展，而是在修复“旧策略保护”和“新重掷动作”冲突后重新检验该路线。

### 搜索实现

1. 搜索树主要由 Go 实现，使用 PUCT 和 determinization。
2. 每个 leaf 调用 Python / PyTorch 网络得到 policy prior 和 value。
3. 当前每个决策只有 8 次 rollout。
4. 训练时使用 Dirichlet noise 和 temperature；评估时可选择 policy argmax 或网络引导 MCTS。
5. 历史上 MCTS16、MCTS64 通常没有超过 argmax，说明当前 value head 和搜索质量可能不足。
6. 不能简单把 Web 的 `n_simulations` 调大，因为当前部署 checkpoint 的 value head 基本未经训练。

### 训练系统与计算约束

1. 训练运行在一台 32 逻辑核、64 GB 内存、RTX 5070 Ti 16 GB 的设备上。
2. 当前 AZ 配置使用 8 个异步 actor。
3. 每个 actor 持有本地 CPU 网络，Go MCTS 同步调用网络。
4. 由于大量小批量 leaf forward 和 CPU 搜索，现有 ExIt 训练主要是 CPU / 内存带宽瓶颈，GPU 利用率很低。
5. 冻结参考策略 anchor 会增加一次昂贵的规则编码器前向；历史实测使单 batch 时间从约 15.6 秒增加到约 37 秒，并使对局吞吐从约 1 局/分钟降到约 0.32 局/分钟。
6. 当前 replay buffer 使用优先采样，`batch_size=256`，每局约执行 4 个训练步骤。
7. 当前计划首先使用本地 CPU inference 保证实现稳定，但允许为了有效训练重新设计 batched inference、缓存或训练拓扑。

### 训练对手

1. F1-D2 是固定的手工基线：
   - F1 状态评分；
   - 两层 minimax；
   - 合法动作模拟；
   - 骰子支付贪心；
   - 重掷期望价值贪心。
2. 它不是完美玩家，也不是神经网络。
3. 当前 ExIt 配方使用：
   - 70% F1-D2；
   - 30% learner historical checkpoint pool。
4. 学习模型不会直接调用 D2 的骰子策略。
5. 长期目标不是只克制这个具体 D2，因此还需要 heldout 规则、阵容、席位和历史策略验证。

## 当前结果与问题

1. 旧环境中，executed imitation warm-start + 16 轮 RL 的策略，对 F1-D2 约 42%–45%；heldout 规则变体约 40%–43%。
2. 当前 Web 模型由该 RL16 模型转换到 AZ 网络：
   - encoder / trunk 和 policy 权重继承；
   - value 与 delta head 是新初始化；
   - Web 当前只做 policy argmax，不使用 MCTS。
3. 当前已有评估约 36.8%（81/220）对 F1-D2。
4. 新版本刚加入正常的每回合重掷流程：双方先掷骰、完成重掷，然后才处理回合开始效果。所有旧 checkpoint 都没有在这种决策流程中训练。
5. 实战日志显示旧模型在重掷阶段明显异常：会重掷出战角色需要的元素骰，然后大量调和补救；整局调和 10 张、只打出 3 张，多名角色满能量不释放爆发。

## 已有贪心骰子策略

F1-D2 已有两种骰子策略：

1. 支付时尽量消耗低价值骰子，保留出战同色、万能骰和后台角色颜色。
2. 重掷时比较当前颜色的保留价值与均匀重投的期望价值，低于期望则重掷。

这些逻辑只属于训练对手和评估基线，不会接入学习模型。

## 历史 ExIt / AZ 结果

1. 从零训练：约 225 局后 argmax 3.6%，MCTS16 4.5%。
2. RL16 warm-start、无锚训练：约 256 局后 argmax 23.2%，MCTS16 15.0%，明显退化。
3. RL16 warm-start、`anchor_beta=0.3`：argmax 34.1%，MCTS16 30.0%；没有超过配对的原始基线。
4. `anchor_beta=1.0` 的旧实验只完成约 12 局、32 次更新，没有足够证据。
5. 历史上推理时直接开启搜索通常比 argmax 更差，推测主要因为 value head 很弱。

## 当前训练配置

- `d_model=32`，1 层 cross，`max_actions=2048`。
- AZ / ExIt，MCTS 每个决策 8 rollouts。
- 8 个 CPU actor，本地 CPU 推理；搜索主要受 CPU 和网络前向限制。
- `batch_size=256`，每局对应 4 个训练步骤，`lr=3e-4`。
- fixed opponent：70% F1-D2，30% 历史策略池。
- policy 学习 MCTS visit distribution，value 学终局 z，另有 delta auxiliary loss。
- 不准备给模型添加手工骰子策略、骰子奖励或 Web 推理兜底。

## 拟议修改与实验

旧 RL16 从未见过重掷决策，因此旧策略在重掷状态上的输出没有教师意义。准备：

1. 普通决策继续使用冻结 RL16 的 policy distillation anchor；
2. 如果一个训练样本的合法动作全部是 `Reroll`，则不计算 anchor loss；
3. 重掷决策只通过 MCTS visit target 和终局胜负学习；
4. 先跑两个 64 局探索臂：
   - A：非重掷决策 `anchor_beta=1.0`，重掷不锚定；
   - B：完全不锚定；
5. 通过后再把胜出配方扩大到 256–512 局；
6. 训练期间冻结 F1-D2 的实现，避免同时改变对手和评估标尺。

## 需要重新考虑的路线选择

不应预设继续 AZ / ExIt 必然正确。至少有三个候选方向：

A. 继续原来的 semantic DMC / RL16 路线，在新环境中让 Q 策略直接学习重掷动作；

B. 使用 RL16 warm-start 的选择性锚定 ExIt，联合训练 policy 和 value；

C. 保留 RL16 主策略，但为随机重掷决策增加可学习的专门模块、分层策略或反事实训练任务，最终仍由网络推理，不使用运行时启发式。
