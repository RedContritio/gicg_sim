# 审查结论

**当前的“语义表示＋合法动作评分”方向值得保留；当前的“8 次模拟 MCTS＋未经验证的 value＋visit distribution 蒸馏”不应继续作为主训练路线。**

“重掷阶段不锚定”修复了一个真实问题：旧模型在新动作上的输出不应被当作教师。但它没有修复更根本的问题：**搜索尚未证明能产生比现有策略更好的训练目标。** 如果教师本身较弱，选择性锚定只能减缓退化，不能使这个教师变强。

我的推荐是：

| 优先级 | 路线 | 定位 |
|---|---|---|
| **主路线** | **C → A：先隔离学习重掷，再恢复 semantic DMC 联合训练** | 保护已确认能力，用模拟器生成重掷的动作价值数据，随后逐步改进普通决策 |
| **备选路线** | **经过独立“搜索改进测试”的 ExIt** | 搜索必须先在冻结策略上证明净收益，才获得训练 policy 的资格 |
| **当前不推荐** | 原样开展“选择性锚定 ExIt vs 无锚 ExIt”两个 64 局实验 | 两臂都依赖同一个尚未验证的弱教师，辨识价值低，且缺少 DMC 对照 |

这不是认为 DMC 原理上优于 ExIt。ExIt 的核心是让规划产生改进，再让网络泛化这种改进；你现在缺的是前半段的证据。另一方面，DouZero 这样的研究说明，面对隐藏信息、可变合法动作和大动作空间，动作编码结合 Monte-Carlo 价值学习本身就是有竞争力的路线，不需要先转换为 AlphaZero 才有进一步提升的资格。:chatgpt-content-reference{index="0"}

以下实现风险均是**需要测试的假设**，不是已经确认的代码缺陷。

## 一、首先把三个目标拆开

| 目标 | 应当证明什么 | 不能用什么替代 |
|---|---|---|
| **消除新重掷流程造成的分布外退化** | 在普通策略保持不变时，学到的重掷选择具有更高续局价值，且新环境整局表现改善 | “少调和了”“保留了更多出战同色骰” |
| **恢复旧模型能力** | 转换没有损坏原有动作排序；新流程下普通决策没有因训练明显遗忘；建立可复现的新环境参考强度 | 直接把新环境胜率与旧环境 42%–45% 横向比较 |
| **真正超过 D2** | 在冻结的新环境、D2、测试协议下，多训练种子达到正式统计标准，heldout 通过非劣检验 | 单个 checkpoint 超过 50%，或只相对当前 36.8% 提升 |

这里有两个重要限制。

第一，**36.8% 并不能全部归因于重掷。** 你同时改变了规则流程、网络接口、动作集合，并引入了没有旧经验覆盖的状态。应当先区分“转换损坏”“重掷不适应”“回合开始效果顺序改变”的贡献。

第二，81/220 的胜率，按暂时忽略场景相关性的普通 Wilson 区间计算，95% CI 约为 **30.7%–43.4%**。这只是根据所给计数计算的描述性区间，不是你要求的聚类区间。它不足以支持精确估计退化幅度，更不能定位原因。

**重掷修复后的模型，应当成为后续“超过 D2”实验的参考模型，而不是继续把未修复的 36.8% 当作主要比较对象。**

## 二、为什么当前 ExIt 配方最可能继续失败

### 1. Q → policy 的转换，可能只保留了排序，没有保留可用的搜索先验

这是我会优先检查的地方。

直接 argmax 只要求：

\[
Q(s,a_1)>Q(s,a_2)
\]

但 MCTS 的先验取决于：

\[
P(a\mid s)=\operatorname{softmax}(l(s,a))
\]

**把 Q 分数直接当 logits，完全可能保持 argmax 不变，却得到近乎均匀的先验。**

例如，假设 Q 的输出范围是 \([-1,1]\)，未经温度缩放直接进入 softmax；在 2048 个合法动作下，即使一个动作取 1、其他动作全取 −1，最佳动作的概率也最多只有：

\[
\frac{e^2}{2047+e^2}\approx 0.36\%
\]

这是条件性的数学例子，并不是断言 RL16 的实际输出就在该范围。但它说明：

> **“复制了 Q head，因此继承了强 policy”不成立。继承了强 argmax，是另一个更弱的命题。**

需要检查的不只是 top-1 一致率，还包括：转换前后的动作分差、先验熵、top-8 概率质量、动作数量变化时的先验变化，以及这些数值与 PUCT 中 value 尺度是否匹配。

尤其要核对：输出激活是否改变、合法动作 mask 是否在归一化前应用、Go/Python 的动作索引是否完全对应、支付组合排序是否稳定。

### 2. 8 次模拟的 visit target，可能主要记录“搜索碰了谁”

以下按你的描述，将 8 rollouts 理解为 **8 次到叶节点并调用网络的 simulations**，而不是 8 次完整终局续局。

在通常实现中，8 次模拟最多访问 8 个不同的根动作，实际可能更少。未访问动作在原始 visit distribution 中没有概率质量。训练网络拟合这个目标，并不等于掌握了它们较差的证据。

动作数量大并不自动使少量模拟失效：如果先验很集中、value 很可靠，少量搜索也可能有效。问题是，你同时具备“大动作空间、可疑的先验尺度、弱 value”三个条件。

Gumbel AlphaZero 的原论文正是针对这一问题指出：**少量模拟下，原始 AlphaZero 的访问计数更新不保证策略改进，即使被考虑动作的价值评估正确也未必成立。** 它改进的是动作选择和训练目标的构造，而不只是增加模拟次数。:chatgpt-content-reference{index="1"}

所以，历史上 MCTS16、MCTS64 弱于 argmax，不宜直接解释成“还需要更大预算”。它首先说明：

**当前搜索尚未获得作为 policy 教师的资格。**

### 3. `anchor_beta=1.0` 不是“保护旧策略不变”

假设单状态目标为：

\[
L=\operatorname{CE}(t,\pi)
+\beta\,\operatorname{KL}(\pi_0\|\pi)
\]

其中 \(t\) 是搜索目标，\(\pi_0\) 是旧策略。忽略网络参数共享等限制，其最优分布是：

\[
\pi^*=\frac{t+\beta\pi_0}{1+\beta}
\]

因此，**β=1 近似意味着把新教师和旧教师各占一半，而不是允许改进、禁止退化。**

如果搜索目标很差，混合之后仍然可能退化。真实网络还会受到 value、delta、其他状态梯度的影响，保护更不等同于硬约束。

而且：

> **重掷样本不计算 anchor，并不能阻止重掷梯度经共享主干破坏普通决策。**

这是选择性锚定方案中最容易被忽略的问题。

### 4. 弱 value 可能是问题，但绝不能作为唯一解释

我建议在任何新一轮 ExIt 前完成以下四类审计。

**价值视角与行动权。**  
你的游戏未必每执行一个动作就交换行动权。快速行动、调和、阶段推进等都需要检查。不能照搬棋类实现，在每条边上机械地把 value 取负；应依据价值所属玩家与控制权变化处理。chance 节点也不能被当成另一位玩家。

**随机节点。**  
重掷结果必须按规则概率采样或求期望，不能像玩家动作一样用 PUCT 选择“最有利骰子”。还要检查克隆状态是否连真实 RNG 状态一起复制，使搜索意外“预知”未来骰子。决策节点与 chance 节点分离，是随机环境规划中的关键结构。:chatgpt-content-reference{index="2"}

**信息集与历史。**  
必须明确 determinization 如何根据可见历史采样，后续双方决策能看到什么，同一信息集的决策是否被不同隐藏世界分别优化。只把隐藏变量填满再跑普通 MCTS，可能产生 strategy fusion：计划依赖未来实际无法区分的隐藏状态。ISMCTS 的研究专门讨论了这些问题，但并不是名字中用了 IS-MCTS 就自动解决。:chatgpt-content-reference{index="3"}

**对手模型与 value 目标。**  
如果 value 学的是“对 70% D2＋30% 历史池的续局结果”，但搜索把对手当作另一个当前网络，或者当作更强的 minimax 对手，搜索与 value 就可能在优化不同问题。

针对固定对手，信息状态下的标量 value 可以有用；但它不是与策略无关的博弈价值。不完全信息博弈中的策略、信念与价值相互依赖，这也是 ReBeL 不能简单沿用普通 AlphaZero 状态搜索的原因。**这里不需要立刻重做 ReBeL，但必须停止默认普通 PUCT 的前提自然成立。**:chatgpt-content-reference{index="4"}

## 三、历史负面结果已经足以决定什么

**足以停止当前组合的默认扩训；不足以否定所有 ExIt 路线，也不足以定位某个实现错误。**

从零训练 225 局表现差，本身不是很有力的否定证据，因为没有合理的样本规模参照。

更有诊断价值的是：从较强 RL16 出发，无锚训练明显退化；增加锚定只能部分缓解；推理时增加搜索通常也不如 argmax。它们共同支持一个工程判断：

> **当前搜索—蒸馏闭环没有显示正向策略改进，不能继续把“训练更久”当作主要修复手段。**

但这些实验还混合了 value 初始化、损失竞争、动作表示、搜索和数据分布变化。不能据此声称“ExIt 已被严格证伪”。

我的处理方式是：**暂停端到端 ExIt，把它拆成可独立测试的教师生成器。教师通过测试后再讨论锚定；教师不过，β 的选择没有战略意义。**

## 四、主路线：先把重掷变成可监督的动作价值问题

### 1. 不需要手工骰子策略，也不需要骰子奖励

你已经拥有可执行规则的模拟器。最有价值的监督不是“应该保留什么颜色”，而是：

> 在同一个可见局面下，执行不同重掷动作，再用相同的冻结续局策略继续游戏，哪个动作的期望终局结果更好？

令 \(I\) 表示玩家信息状态，\(a\) 表示重掷动作，\(\pi_c\) 为冻结的己方续局策略，\(\rho\) 为冻结的对手策略或混合：

\[
Q_{\rm reroll}^{\pi_c,\rho}(I,a)
=
\mathbb E_{h,\xi}[z\mid I,a,\pi_c,\rho]
\]

其中 \(h\) 是与信息状态一致的隐藏世界，\(\xi\) 是未来随机性。

这个目标使用的仍然是终局胜负。**没有增加“保留同色骰”的奖励，没有调用 D2 为学习方决定重掷，也没有运行时兜底。**

需要明确：这是冻结续局策略下的 \(Q\)，不是最优 \(Q^*\)。它的用途是产生可验证的一步改进，之后随着策略改善迭代重生成数据。

### 2. 两种标签来源，应分阶段使用

**第一种：完整终局反事实续局。**

对同一根状态的多个候选动作分别执行续局，得到：

\[
\hat Q(I,a)=\frac1K\sum_{j=1}^{K}z_j
\]

优点是不用信任新 value。缺点是昂贵，而且胜负方差较大。

候选至少包含当前模型动作，同时加入模型提出的其他动作和具有覆盖性的随机合法候选；不要只评估旧策略 top-k，否则可能永远看不到被旧模型严重低估的重掷选择。

**第二种：随机转移后使用冻结、已校验的 value。**

先完成相关重掷流程和回合开始效果，推进到明确的决策边界，再用冻结 value 估计续局：

\[
\hat Q(I,a)
=
\frac1K\sum_{j=1}^{K}V^-(I'_j)
\]

这适合批量生成大量数据，但前提是 \(V^-\) 已在这些后继状态上被终局数据校验。**大量采样可以降低骰子随机性的方差，不能消除 value 的系统性偏差。**

我的顺序是：**少量终局续局验证方向 → 冻结 value 加速扩充 → 持续保留独立终局抽查。** 不要反过来，让随机 value 先生成大量“高置信度”标签。

### 3. 同一根状态的配对比较，比孤立采样更有价值

可以在不同候选之间耦合隐藏世界和未来随机数，估计：

\[
\Delta(I,a)
=
\hat Q(I,a)-\hat Q(I,a_{\rm current})
\]

其方差满足：

\[
\operatorname{Var}(X-Y)
=
\operatorname{Var}(X)+\operatorname{Var}(Y)
-2\operatorname{Cov}(X,Y)
\]

因此，在产生正相关的有效耦合下，配对比较能比两组独立续局更精确。

实现时要保证每个候选的边际随机分布仍然正确。简单重置同一个 PRNG seed，不一定能在分支调用次数不同后继续保持有用配对；骰子、抽牌等随机流最好分开管理。

还有一条必须遵守：

**用于选出最佳候选的随机样本，不能同时作为证明它更强的唯一评估样本。** 否则是在报告采样噪声中的赢家。

### 4. 8-rollout＋终局 z 是否过于稀疏？

**对当前规模与拓扑而言，我认为是；但“稀疏”和“有偏”需要分开。**

正确模拟、固定续局策略下的终局 Monte-Carlo 样本，不会因为只有 8 次就必然有偏，但会非常嘈杂。作为直观量级：即便把 8 次完整终局样本全部用于评估一个动作，在真实胜率 50% 附近，胜率估计的标准差也约为 **17.7 个百分点**。你现在的 8 次模拟还要分给多个动作，而且通常不是终局样本。

value bootstrap、错误信念、机会节点处理或从噪声估计中取最大值，则会引入额外偏差。

因此，我支持**增加重掷训练数据的比较预算**，但不优先支持“把所有重掷 MCTS 从 8 调到 64”。首先应改变预算用途：让它更集中地回答候选之间的价值差，而不是生成极稀疏 visit target。

## 五、动作结构、重掷 head 与 replay 应怎样修改

### 1. 先使用独立的整动作 reroll Q head，不急着做完整分层控制器

建议保留 RL16 的普通动作评分路径，增加：

\[
Q_{\rm reroll}(I,\text{各颜色重掷数量})
\]

它应读取骰子数量、角色和手牌的费用语义、当前资源、回合阶段以及相关 hook，而不是读取手工计算的“骰子价值”。

**不建议把每颗骰子独立分类为“保留/重掷”。** 骰子之间存在费用阈值和组合关系；需要三颗同色骰才能用技能时，独立边际判断可能不够。更稳妥的是对完整数量向量评分，或者使用有条件依赖的自回归策略。

另外，先测量重掷动作数，不要把 `max_actions=2048` 当成所有阶段的实际复杂度。若一次性选择各颜色重掷数量，颜色 \(c\) 有 \(n_c\) 颗骰子，那么组合数最多为：

\[
\prod_c(n_c+1)\le 2^D
\]

例如 \(D=8\) 时最多 256 种。你的主要动作膨胀可能在支付阶段，而不是重掷阶段。

### 2. 支付组合不能粗暴删除，但可以结构化

不同支付方式留下的骰子不同，因此一般不能视为等价动作。

建议将策略分解为：

\[
P(a)=
P(\text{技能/出牌/切换等语义动作})
\cdot
P(\text{支付、目标等参数}\mid\text{语义动作})
\]

最初不一定要改成多步运行时决策，也可以保留最终完整动作 argmax，只在网络和搜索内部共享语义动作的编码。

这能减少一个技能因为有大量支付组合而获得过多先验质量、消耗过多搜索预算的问题。只有**规则语义上确实等价**的重复动作才能直接合并；留下不同资源的支付不能随意剪掉。

若以后采用候选采样搜索，还需要处理候选采样分布与策略分布的关系，而不是简单取 top-k 后把其他动作当成劣动作。Sampled MuZero 对这种复杂动作空间下的采样与策略改进作了专门处理。:chatgpt-content-reference{index="5"}

### 3. replay 应按决策类型分层，但别把过采样当成新数据

我支持重掷单独分层。初始可以让重掷占训练抽样约三分之一，其余保留普通决策；这是可测试的起点，不是理论最优比例。

更重要的是记录：每类独立根状态数量、每条样本平均重用次数、数据年龄、对手版本、环境与规则版本。

按你当前配置，每局对应：

\[
4\times256=1024
\]

次状态抽样。如果一局只有 \(L\) 个有效学习决策，平均抽样重用量级就是 \(1024/L\)。增大重掷抽样比例，可能只是反复拟合几十个高度相关的根状态。

**初始恢复实验建议关闭 PER，先用透明的类型分层采样。** 恢复 PER 时再明确优先级定义和重要性修正，避免随机胜负造成的高误差长期占据采样。优先经验回放本身会改变采样分布，原论文也专门处理了相应偏差。:chatgpt-content-reference{index="6"}

旧环境的终局标签也不能无条件混进新环境 replay。规则流程已经改变，必须区分版本；旧数据可以用于兼容性测试，但不自动是新环境有效的价值监督。

## 六、怎样保护旧策略，并训练出可用的 value

### 1. 我支持先冻结，但冻结的是普通能力，不是冻结所有新表示

第一阶段建议：

**普通动作 encoder/trunk/head 冻结；新增 reroll 分支或 adapter；value 使用独立 head 或小 adapter；暂时关闭 delta auxiliary。**

重掷分支需要直接接收到新增阶段、数量向量等必要信息。如果旧表示从未保留这些信息，仅在冻结特征上接一个线性 head 可能不够，这时应增加小型可训练适配器，而不是立刻解冻全部主干。

这样做的优势是，普通决策保护成为结构性保证，不需要每个 batch 再跑一遍昂贵 anchor。

解冻顺序应由验证决定：先新模块，后共享交互层，最后才考虑规则编码器。每次解冻都检查固定普通状态面板上的动作变化和新环境配对胜率，而不是只看总 loss。

### 2. RL16 的 Q 可以用于 value 初始化，但必须重新确认它代表什么

在真正的同策略动作价值下：

\[
V^\pi(I)=\sum_a\pi(a\mid I)Q^\pi(I,a)
\]

对于确定性策略，可写成 \(Q^\pi(I,\pi(I))\)。

但 RL16 的 Q 可能来自探索策略、历史对手混合和旧环境。因此：

\[
\max_a Q_{\rm RL16}(I,a)
\]

**不能直接被解释成新环境、当前贪心续局下的可靠 value。** 好的动作排序不等于好的绝对价值校准，取最大值还可能挑中估计误差。

我会在同一批新环境数据上比较三种初始化：

| 估计器 | 作用 |
|---|---|
| 阶段条件常数基线 | 检查网络是否只学会了胜率基准或回合进度 |
| 校准后的 \(Q_{\rm RL16}(I,\pi_0(I))\) | 利用已有 Q 信号，但重新映射到新环境终局结果 |
| 冻结普通主干、新训练的 MC value head | 用真实新环境轨迹直接学习当前冻结续局价值 |

校准可使用简单单调映射；训练/验证必须按整局或场景拆分，不能把同一局中的相邻状态分别放入两边。

**不要只比较 value MSE。** 还要看动作分歧状态上，value 是否能把更好的分支排在前面。一个仅凭生命值和回合数就得到不错 MSE 的 head，可能仍不具备搜索所需的局部辨别力。

### 3. 一个必须检查的标签错误

实际对局的终局 \(z\)，只能直接监督实际执行轨迹中的状态。

**不能把这局最终胜负贴给所有搜索过但未执行的分支。** 反事实分支需要自己的续局结果，或明确的 bootstrap target。若这里存在错误，提高训练量只会更快拟合错误目标。

### 4. 锚定应按可信范围，而不是仅按 `all(actions == Reroll)`

“整行都是 Reroll 就排除”可以作为临时补丁，但长期我建议显式使用**阶段标识**，而不是从合法动作集合反推阶段。确认、零重掷、特殊规则动作等都可能破坏这个判断。

更一般的 anchor 应依据：

- 旧模型是否覆盖该阶段和动作语义；
- 旧动作排序在独立样本中是否可靠；
- 当前状态是否属于新流程引入的明显新分布。

这里的可信度不能直接等同于 softmax 尖锐程度或 Q 分差；前面已经说明，它们可能只是输出尺度的结果。

在混合新旧动作的状态上，若只约束旧动作子集，需要明确约束的是**子集内部排序**还是**总概率质量**。只归一化子集做 KL，不能保护子集总质量；反过来强行保留旧子集质量，又可能压制必要的新动作。

**早期用明确阶段门控＋冻结模块，比立即构造复杂的“自动可信度 anchor”更可靠。**

## 七、对手混合与规则泛化：70/30 不是当前主要矛盾

**不能仅凭 70% D2 就判定过拟合。** 目标本来就包含稳定超过 D2，在它身上投入较多训练资源合理。

真正需要检查的是，30% 历史池是否具有行为多样性。如果只是同一路线的几个相邻 checkpoint，形式上是策略池，实际上可能仍然只有一种打法。

恢复阶段，我建议固定一个对手混合不动，以免同时改变算法和任务分布。恢复成功后，再比较例如“50% D2＋25% 多样化历史策略＋25% 近期策略”的混合；比例是实验起点，不是推荐定值。

历史策略应按对战表现和行为差异挑选，而不是机械地每隔若干局存一份。对手池与经验博弈矩阵的思路可以借鉴 PSRO，但目前没有必要实现昂贵的完整元博弈求解器。:chatgpt-content-reference{index="7"}

同时必须质疑两个泛化前提。

**不用 ID 不等于不会记忆。**  
完整规则结构本身也可以成为某张牌的唯一指纹。应测试一致重命名、实体顺序置换、语义等价的 DSL 改写、未见过的效果组合，而不只是换数值。

**小模型不等于更泛化。**  
`d_model=32`、一层交互也可能把费用、资源阈值、触发顺序和跨角色关系压缩得不够。网络扩容不应优先，但在高质量监督数据已经生成后，应做一次冻结数据集上的容量对照：若小模型连训练集上的动作价值排序都学不好，继续加 RL 数据不是唯一答案。

此外，当前描述缺少明确的历史输入。不完全信息下，同一可见棋盘可能对应不同的合理信念。至少要审查当前状态是否包含足够的已公开动作、抽牌/弃牌/揭示信息；否则 determinization 与网络都可能丢失决策依据。

**最终 heldout 不能拿来做这些反复设计选择。** 应另设开发用规则变体，最终 heldout 保持锁定。

## 八、系统拓扑确实在放大算法问题，但先改最有把握的部分

当前问题可能形成反馈：

\[
\text{小批推理昂贵}
\rightarrow
\text{搜索预算很低}
\rightarrow
\text{教师信号弱}
\rightarrow
\text{训练难改善}
\rightarrow
\text{继续增加昂贵搜索}
\]

但在证明教师有效前，不建议先做一次大型搜索系统重构。

### 先做：重复计算与线程审计

冻结 RL16 的 anchor **没有必要在每个 batch 重新完整计算**。可以在样本入库时计算并保存教师分数，或者离线批量补齐；静态规则编码也可缓存。

缓存必须带教师版本、规则版本、动作签名等信息。可训练编码器的中间输出不能跨更新无条件复用，否则会引入陈旧表示或切断预期梯度。

还应检查 8 个 actor 是否各自启用了大量 BLAS/OpenMP 线程。CPU oversubscription 是 PyTorch 多进程文档明确提示的性能风险。:chatgpt-content-reference{index="8"}

`batch_size=256`、`max_actions=2048` 与逐动作规则展开相结合，也值得重点检查：实际开销可能来自重复编码、padding、序列化和内存搬运，而非模型宽度。

### 再做：跨 actor 的集中批量推理

将 Go 环境与搜索留在 CPU，神经推理集中到 GPU，方向合理；SEED RL 展示了集中加速推理的系统价值。:chatgpt-content-reference{index="9"}

但你的拓扑有一个具体限制：

> **8 个同步 actor 每个只挂起一个 leaf 时，最多只有约 8 个请求可供合批。设置 batch=64 不会自动得到 64 个请求。**

需要每个 actor 同时推进多个环境/树，或允许一棵树保留多个待评估叶节点，并正确处理重复选择与取消。还要设置短等待上限，避免为了凑 batch 使搜索长期阻塞。

是否改完一定更快，要实测。小网络可能受 IPC 和数据准备主导；D2 自身的两层模拟也可能成为新的瓶颈。

**比较指标应是每小时有效独立根状态、有效续局比较和最终策略收益，而不是单独追求 GPU 利用率。**

## 九、最小、低成本的证伪实验

我建议把资源从“两个端到端 ExIt 臂”移到下面的顺序实验。后一个实验必须由前一个结果授权。

### 实验 0：不训练，检查转换与环境契约

从旧环境和新环境采集普通决策状态，比较原 RL16 Q argmax 与转换后 policy argmax。使用同一合法动作集合，排除真正的数值平局后，不应出现无法解释的差异。

同时建立小型可精确求解测试：chance 期望、连续行动权、终局符号、零重掷、双方重掷完成后的 hook 顺序、合法动作上限、隐藏信息不变性。

特别做一个测试：**保持玩家信息状态不变，改变实际隐藏世界；在固定搜索自身随机源时，根决策不应偷偷随不可见真相变化。**

**Go：** 所有契约测试通过，转换差异均可解释。  
**No-go：** 任一价值符号、信息泄漏、动作错位、静默截断错误未解决。此时停止所有路线比较。

### 实验 1：先验证局部教师，不更新 policy

用冻结策略收集少量重掷根状态和普通决策分歧状态，比较：

| 候选教师 | 要回答的问题 |
|---|---|
| 当前 MCTS8 | 原教师到底比 argmax 好还是差？ |
| 使用校准 Q / 预训练 value 的 MCTS8 | value 修复是否足以让搜索有收益？ |
| 重掷候选的直接反事实续局比较 | 不建深树，能否产生更清楚的改进信号？ |

初始可用 **16–32 个根状态**，每根先比较当前动作与 1–3 个候选，每候选少量续局；只给仍有判断价值的分歧追加预算。

这只能筛查明显错误，不能精确证明几个百分点收益。完整终局续局也不免费：**按环境执行步数、网络前向次数与墙钟计费，设置总上限，而不是把几千个分支叫作“小实验”。**

选择动作与验证动作收益使用独立随机样本。

**Go：** 教师在独立验证中有正向配对收益，并值得其计算成本。  
**No-go：** 充分追加后收益上界仍不高于零。  
**未决：** 区间跨零且预算耗尽，暂停该教师；不能宣布成功，也不能宣布整个算法原理失败。

### 实验 2：把两个 64 局探索臂换成真正有区分力的对照

| 实验臂 | 普通策略 | 重掷训练 | 目的 |
|---|---|---|---|
| **A：DMC 恢复臂** | 延续 RL16 的 Q 学习 | 终局回报＋类型分层 replay | 检验最简单的已验证路线能否适应新流程 |
| **C：隔离重掷臂** | 冻结 RL16 普通路径 | 独立 reroll Q，使用通过实验 1 的标签 | 检验退化是否主要可由新阶段隔离修复 |

二者都保留未训练的新环境 checkpoint 作为固定对照。先各用一个训练 seed 做 64 局冒烟测试；表现值得继续的路线，再增加独立训练 seed，而不是立即把一个幸运 seed 拉长。

同时报告等对局数结果和等墙钟结果。前者衡量样本效率，后者衡量你这台机器上的实际价值。

**64 局足以发现明显遗忘、loss 异常、动作塌缩和严重退化；不够可靠选择小幅领先的配方。** 如果评估也只有 64 个近似独立对局，在 50% 附近，普通 95% 误差范围就约为 ±12 个百分点，聚类后还可能更宽。

### 实验 3：只有教师通过后，才做锚定 ExIt 消融

先使用同一批、已验证存在改进的目标，离线比较有锚与无锚蒸馏，避免两个训练臂同时产生不同质量的教师，导致无法归因。

之后才考虑在线 ExIt。低预算下，可测试基于动作价值改进的目标，而不是默认使用稀疏访问计数；Gumbel 方法中的 completed-Q 目标提供了一个研究依据，但其改进结论依赖价值估计等条件，不能迁移成你这个不完全信息实现的自动保证。:chatgpt-content-reference{index="10"}

**没有独立 teacher gain，就不进入这个实验。**

## 十、每阶段的 go / no-go 与正式完成标准

下面是建议预注册的门槛。数值容忍度应在看结果前确定，表中的 3 个百分点只是可讨论的起点。

| 阶段 | Go | No-go / 暂停 |
|---|---|---|
| **环境与转换** | 契约、信息隔离、动作对应全部通过 | 任一未解释的正确性问题 |
| **重掷分布外修复** | 独立续局比较显示正收益；冻结普通路径在相同状态上输出不变 | 只有行为日志变漂亮，没有价值收益；或普通路径意外变化 |
| **新环境能力恢复** | 多 seed 配对评估优于未修复参考，并建立稳定的新环境基准 | 明显遗忘或收益仅出现在单 seed |
| **DMC 联合改进** | 相对“已修复参考”继续改善，开发规则与历史对手无明显损失 | 只超过 36.8%，却没有超过修复后的参考 |
| **ExIt 获得扩训资格** | 冻结网络上的搜索改进和蒸馏后 argmax 改进均成立 | 搜索只改善自己的估值，或蒸馏持续伤害部署策略 |
| **正式超过 D2** | 满足预注册的多 seed、聚类 95% CI 与 heldout 非劣标准 | 仅点估计超过 50%，或合并大量对局掩盖训练 seed 失败 |

正式统计建议特别注意三点。

**场景才是成组比较单位。**  
同一规则、阵容和随机情境下的双席位双布局结果必须留在同一个统计块中，不能当成四个完全独立样本。训练 seed 与场景如果是交叉设计，应使用保留这种结构的重采样或模型，而不是简单把所有胜负塞进一个二项区间。强化学习评估中忽略训练运行差异，确实可能改变实验结论。:chatgpt-content-reference{index="11"}

**“稳定”不能只由池化均值表达。**  
除整体区间外，应报告每个训练 seed、席位和布局的结果。正式阶段优先争取至少 5 个独立训练 seed；资源不足时可以减少，但必须承认对训练稳定性的判断更弱。大量测试对局不能完全替代独立训练。

**heldout 使用非劣检验。**  
例如预先规定相对已修复参考的容忍下降为 3 个百分点，则要求 heldout 胜率差的 95% CI 下界高于 −3 个百分点。未发现显著下降，不等于证明没有明显退化。

还要给正式评估留足预算。按独立伯努利近似、真实胜率 55%、使用双侧 95% 区间且希望约 80% 概率通过“下界高于 50%”，所需量级约为 **780 个独立对局**；真实胜率 53% 时约为 **2200 个**。这是理想独立条件下的近似功效计算，场景相关与训练 seed 方差会改变需求。

因此，工程目标最好不是“勉强做到 50.5%”，而是形成足够的真实优势，让正式证明在预算内可行。

## 十一、最终优先级与应该立即停止的路线

### 具体修改顺序

| 顺序 | 修改 | 理由 |
|---|---|---|
| **P0** | 审计转换、动作截断、value 视角、chance、隐藏信息与版本一致性 | 正确性问题会使所有算法比较失效 |
| **P1** | 冻结普通路径，隔离重掷；把重掷目标改成可验证的续局 Q | 同时控制遗忘与教师质量 |
| **P2** | 决策类型分层数据；缓存冻结教师与静态编码；暂关 delta/PER | 提高监督可解释性，消除明显重复成本 |
| **P3** | 比较 Q 校准与 MC value；通过后再扩充 bootstrap 标签 | 为搜索和反事实数据加速提供可靠基础 |
| **P4** | 逐步解冻，继续 DMC；增加普通关键动作的反事实覆盖 | 从“修复”进入“真正变强” |
| **P5** | 按 profile 改集中合批拓扑；有 teacher gain 后再投入 ExIt | 避免高效生成低质量目标 |
| **P6** | 高质量固定数据上的容量对照、对手池扩充 | 在证据支持时解决表示和泛化瓶颈 |

**只能优先改一个方面时，我选训练目标。** 更具体地说，是停止默认蒸馏未经证明的 MCTS8 visit target，改为在保护普通策略的条件下，学习可以独立验证的重掷续局价值。

不是优先增加 rollout，不是优先扩大模型，也不是优先扫描 β。系统优化中的缓存与线程修复可以顺手做，但不能替代目标正确性。

### 应该立即停止

应停止**随机或未经验证的 value 驱动全局搜索后，直接训练强初始化 policy**；停止在没有搜索收益证据时继续放大无锚 ExIt；停止把“重掷取消 anchor”视为普通能力已经受保护；停止用旧环境胜率与新环境胜率直接归因；停止仅凭调和次数、爆发次数或一次 64 局结果宣告路线成功。

同样应停止默认“小模型＋无 ID”已经保证规则泛化，以及为了提高 GPU 利用率而先进行大规模重构。

## 最有希望从 42%–45% 走向真正超过 D2 的杠杆

我认为最有希望的不是“让 MCTS 更像 AlphaZero”，而是：

**用精确规则模拟器，在关键决策处生成比单条执行轨迹更丰富的动作比较数据，并把这些改进压缩回原有语义 Q 策略。**

先用于重掷，因为它是明确的新阶段，容易隔离训练；证明有效后，再扩展到支付、调和与出牌取舍、切换、爆发时机、结束回合等关键动作。它们可以继续通过终局结果或校验后的续局价值学习，不需要手工奖励。

仅修复重掷，可能让模型恢复甚至有所超越，但没有证据保证它能跨过 D2。**真正超过 D2 的阶段，最终需要允许普通策略改进，而不是永久锚在 RL16。**

因此我的最终判断是：

> **批准 C → A 作为主路线；批准有限预算的搜索教师验证；不批准当前选择性锚定 ExIt 原样扩训。**
>
> **先证明新动作学对了，再证明旧能力没有丢，最后证明新策略真的超过 D2。搜索应当凭独立增益获得进入训练闭环的资格，而不是因为它叫 AlphaZero。**
