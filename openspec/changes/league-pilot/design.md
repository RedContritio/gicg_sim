# 设计

冻结四个锚点：41/20k、42/12k、43/20k、43/30k；保留弱但可能互补的策略。
两名训练者都以43/20k权重初始化，使用新优化器与新经验池，各新增6000 frames。
这不是原30k实验的继续，原记录和全部检查点保留。

主策略：random 20%、D2 20%、冻结策略池60%。
冻结池内依据初始主策略的成对对战得分p按 max(0.05,(1-p)^2) 归一采样。
初始测量固定16个场景交换席位，种子115000；有限样本权重只是本轮调度依据。
针对策略：100%对抗初始43/20k，epsilon=0.3；主策略epsilon=0.2。
其余沿用原配置（lr=0.0003、batch32、每局4次更新、池10000）。
本轮对手与采样权重冻结；下一轮才更新，避免异步文件到达影响对手分布。

联赛池保存计划标识、完整权重分布、RNG和抽样次数，进入完整runtime checkpoint。
只允许通过league.run和原计划恢复，拒绝静默改计划。正常训练登记、关闭与恢复
仍走tools.runs.train。既有opponent ring不作为本轮联赛池，避免FIFO淘汰锚点。

结束后6个模型做完整15组配对（每组32场景交换席位），初始模型与两候选还做五档基线。
评估固定新种子116000；对战960局，加基线960局，共1920局。
报告胜负矩阵和每列覆盖增益。候选若对至少一个旧对手超过旧池最佳得分5个百分点，
标记为需要复核的入池候选；这只是后验筛选，不自动晋升或删除任何策略。
不要求新策略打赢全部旧模型，也不以单一Elo或平均分抹去克制关系。

源码兼容：实验工具在tools下，生产来源指纹不变。远端保留原始训练源码；
新工具哈希单独写入不可变计划并在恢复前校验。禁止将本机重构源码同步覆盖远端。
