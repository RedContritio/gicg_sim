# 审计与测试设计

## 效果绑定

解释器在注册 hook 时，从闭包捕获环境解析 AST 中的 counter 方法访问，保存只读审计元数据。
来源是否为系统规则由实际加载路径记录，不把所有同类型 hook 一概视为系统。
审计关联 CounterAccess、OrderIDs、BuffDefinitions 和有效 IR，输出读写位置、绑定、期限及死亡策略。
这些元数据不改变 hook 执行，不作为 NN 特征。

CLI 先解析训练配置的 extends、队伍、牌组和声明池，再调用同一个 production factory。
默认检查五范式 default 及 DMC Stage 3 自定义卡池配置；可重复传 --config 扩大范围。
缺少绑定/表示或出现未分类公开字段时退出非零。默认 Go 测试检查当前角色组合，并有故障注入回归。

## 随机序列

12 个固定种子使用实际卡牌、两角色镜像队伍和固定骰增加可执行交互密度。
先抽动作类别，再抽该类别中的合法动作，避免费用支付排列数量主导采样。
每一步比较合法动作、完整可序列化状态与双方观测；原始对局保留日志，分支不重复写源日志。
最终完整回放再比较状态。等待输入节点不导出文件 checkpoint，继续检查池化快照与克隆，并在后续选择中验证暂停逻辑。

另一组 24×160 操作序列，仅使用简单数组参考模型模拟生成、FIFO 抵消、逐层到期和整组清空。
参考模型不调用引擎的计数或排序函数，避免仅把实现抄进测试。

## 可观测性

显式枚举 Game 字段的输入/隐藏/规则/暂存/已知缺口策略，新增未知字段导致审计失败。
通过状态对验证公开状态改变时 NN 输入改变；对隐藏身份与随机源做反向不泄漏检查。
扩展 meta 的 18 维由 Go/Python 常量统一约束，网络投影自动读取该常量。

具体覆盖结果见 [coverage.md](coverage.md)，输入语义与保留缺口见 [observability.md](observability.md)。
