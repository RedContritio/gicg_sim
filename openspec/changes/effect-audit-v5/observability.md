# NN 可观测性审计

## 已覆盖与修复

- 生命、能量、附着、骰子、回合计数等量由 counter 段提供；独立层由 buff 行提供。
- 活跃 buff 的次数、期限、进度、所属方/角色、产生顺序、结算组及实际 hook 引用可见。
- 无 buff 时也能看到双方结束声明和先结束方，消除原观测中转移不同而输入相同的一类状态。
- 回合上限和固定骰设置影响环境转移，现在作为公开规则配置进入输入。
- 等待操作的类型与强制标志可见；准备技能与近期伤害有既有 typed 段。
- 观测转为训练用浮点输入时保留新增元数据；默认网络 meta 投影自动采用 18 维。
- 所有 Game 字段均有显式策略分类；新增未分类字段使默认审计失败。

meta 顺序：`phase, round, is_my_turn, own_ended, enemy_ended, first_end_relative,
max_rounds, pending_kind, pending_forced, fixed_roll, fixed_dice[8]`。
first_end_relative=-1 表尚无先结束方；固定骰模式为 0 时后八项为零，不暴露随机种子。

## 有意隐藏或不作为决策输入

随机源/种子、绝对生命周期编号、对方手牌身份和牌库顺序不能泄漏。
敌方骰子可按训练场景的 obs_mask 有意屏蔽。日志/诊断附件不属于规则状态。
奖励累计/胜者作为训练目标处理；抽牌时间等奖励记账字段不据此宣称属于完整策略输入。

## 明确保留的缺口

1. 通用暂停程序的剩余效果/调用上下文尚未完整编码。当前测试证明选择后的模拟与恢复一致，
   不能据此证明无记忆网络的输入具有完整 Markov 性。
2. 通用 SupportInst 槽位与 SpecialtyCardRef 的独立身份没有专用 NN 表达。
   当前训练牌的支援/天赋主要通过 counter 实现；扩展到通用槽位机制前须单独迁移与验收。
3. 部分旧式卡牌/技能引用 counter 仍是旧数值表达。当前可以观察其值，但未证明摆脱注册 ID 依赖。
4. 当前 AST 扫描解析闭包捕获的 counter proxy；动态 receiver、局部别名和复杂闭包依赖并非完整静态分析。
5. 公开历史摘要用于 determinization，未全部输入无记忆 NN；信念状态/循环网络属于后续设计。

因此本轮完成的是“审计并修复确定的遗漏”，不是对所有扩展机制作完整可观测性保证。
旧回放的三个 meta 字段无法恢复新增信息，应重新采样；严格 resume 不接受新旧输入形状混用。
显式 adaptation 保留旧投影前三列，其余置零并使用新优化器。
