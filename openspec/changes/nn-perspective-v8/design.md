# 视角与规则身份

## 数据契约

Counter 区始终按静态 P0 角色、P1 角色、P0 玩家、P1 玩家、全局排列。
min/max、SID、值、规则 IR 和实体的源 SID 使用同一个身份空间，静态缓存
仍可整局复用。引用 counter 继续输出存在性，具体目标在实体规则引用中。

动态 meta 从 18 扩至 19 个字段，本轮追加
第 18 号字段 observer（0 或 1）。Turn 可能不同于 observer，尤其是死亡后的
强制换人。观测默认使用 ActingPlayer；禁止通过 Turn 推测决策方。

手牌、结束状态、伤害事件、准备技能、buff/支援/天赋归属仍为相对视角。
网络保持 canonical counter/SID 注意力绑定；结构化位置读出在送入 readout
前按 observer 转成己方在前，包括角色属性、骰子和存活人数。批中每行独立
转换，重排可微。技能引用池为集合均值，不依赖双方排列。

## 五范式和运输

AZ/PPO/DMC/BC 共用 ActorCritic；CFR 的独立 trunk 调用同一结构化转换函数。
采样、静态去重、回放及异步通信保留 observer，counter 不再因决策方变化
而重新排列。Go actor 直接取得引擎 canonical counter；服务端沿用静态范围
归一化。敌方骰子遮罩按 canonical 标签选择真实敌方，不遮住己方。

观测版本与网络 meta 投影形状改变，旧权重/采样继续由来源入口拒绝；不迁移
v7 产物。本轮只进行临时工作区内的短程验收，不启动 5070 Ti 正式长训。

## 验收

独立 oracle 使用 SID→引擎 counter 排列核对所有有效槽位，不复制被测函数
的分组排序。覆盖非对称队伍、双方视角、引用效果、克隆、快照恢复，以及
Turn=P0、ActingPlayer=P1 的实际伤害死亡强制换人边界。
Python 检查归一化、遮罩和混合视角结构化读出，五范式 smoke 检查运输/训练/恢复。

后续：显式暂停执行帧；动作条件实体查询；公开历史/记忆与重新采样的学习实验。
