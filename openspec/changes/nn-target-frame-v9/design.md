# 数据帧与剩余执行栈

## 已实现的程序

`TargetFrame` 保存 PC、出牌方、卡牌引用、战斗行动标记、目标模式和已应用费用规则集合。`PendingCard` 保留为 API 类型别名。只有 `TargetAwaitChoice` 可作为外部暂停边界；选择合法目标后，先移除等待帧，再进入 `TargetInvokeCard`，退出时标记 `TargetConsumed`。帧必须是当前活动实例，旧指针不得再次调用。

恢复只执行卡牌剩余效果。费用支付、移出手牌、加入弃牌和出牌日志已经发生，不重复执行。无效目标索引保持状态。快照深拷贝费用规则集合；检查点版本 2 可保存并在相同注册布局、规则源和引擎构建中恢复此边界。检查点在临时内存中验证 PC、角色方、目标模式、卡牌、modifier hook 和阶段后再覆盖接收者；它不是合法对局来源的真实性证明。日志附件仍不属于游戏检查点。

## NN 传输

沿用 16 字段实体行，增加 kind=5 的程序帧和 kind=6 的已应用规则绑定，BuffEncoder 类别词表从 5 扩为 7。五种范式使用同一编码器。

| 字段 | 执行帧含义 |
| --- | --- |
| 1 / 2 | 相对所有者 / 出牌角色槽位（不适用为 -1） |
| 3 | 当前程序入口及参数是否完整可见；不是整个解释器栈完整标记 |
| 4 / 5 | 目标模式 / 当前 PC |
| 6 | 当前单帧绑定位置 0；绑定集合没有顺序语义 |
| 7 | canonical 卡牌或已应用规则的 active hook slot；未知为 -1 |
| 8 | 程序原语：0 卡牌选目标、1 独立换人、2 重放兼容路径 |
| 9 / 10 | 战斗行动 / 强制选择 |
| 12 | 5 帧、6 规则绑定 |

卡牌归属方可见已应用的规则引用；其他视角不输出其数量或真假条件，并总是标为不完整。没有可编码规则的 native hook 不输出原始 ID，归属方也标为不完整。换人原语无需伪造卡牌规则引用。钩子重编号不应改变语义，费用规则绑定重排不应改变网络输出。

## 尚未迁移的程序

`resume` 存在时始终输出重放兼容路径和 complete=0，仍拒绝导出它的检查点。`continuation.go` 的根快照、选择历史和重放闭包仍在使用。没有把闭包、RNG、私有局部变量直接输入 NN。

完整迁移需要将下列状态由宿主调用栈移到可复制的数据结构，不能只补几个 pending 字段：

1. DSL 语句 PC、表达式求值中间值、局部环境、返回栈及类型化对象引用。
2. 伤害各阶段、反应追加效果、hook 游标及上下文；伤害日志和 mutable context 的引用关系。
3. 延迟队列、技能/卡牌尾部、回合结束与开始阶段的游标。
4. 每个可暂停程序的所有者和局部变量可见性策略。

下一阶段先建立类型化指令及局部槽位，再迁移能产生输入请求的 DSL/native builtin 调用链。针对嵌套伤害、连续死亡、末尾语句、延迟效果和双方回合结算，逐个验证暂停时克隆、分支修改、RNG、日志与独立进程恢复。直到所有这些路径通过，才能移除根快照重放，也才能声称 NN 可见暂停执行程序完整。
