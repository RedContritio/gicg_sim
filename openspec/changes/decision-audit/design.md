# 诊断协议

模型：联赛 main，SHA256 `f1d24a25a9c576e95c7214cf9902a8b8a0cb36e17831d146ae3a8173af97f3e6`。
在 `.56` 原生产源码上运行，仅部署 tools/experiments/decision_audit；不训练、不修改奖励或网络。

- 新种子 118000，8 个场景交换席位，共 16 局 NN 对 F1-D1（启用骰子支付启发式）。
- 每个 NN 决策记录 Q 值、D1 候选最佳 F1、两动作即时效果、支付、是否有技能却结束。
- D1 独立审计 RNG 与真实对手 RNG 分开。眼前 F1 相同的动作差异不算即时判断错误。
- 每局对 NN/D1 动作索引不同的状态做容量 2 的蓄水池抽样，不按事后胜负挑选。
- 每个样本分别执行 NN 首步和 D1 首步，之后己方由 NN 或 D1 控制，对手始终 D1。
- 每种后续控制策略重复两次；两种首步使用相同未来引擎种子与玩家 RNG 种子。
- 固定当时隐藏状态，只重设未来随机数；这是条件续打，不能当作对信息集最优价值的估计。
- 共最多 32 个分歧状态、256 局续打；所有分支必须到达终局，超步数即报错。

即时差距不等于长期失误；支付差异不等于浪费；续打只有两次重复，不能给单状态确定性判决。
不同状态可能来自同一局，不能作为独立对局计算高置信度结论。
诊断工具自身哈希和模型来源随结果保存，失败保留已完成记录。
