# NN 实体表达 v7

本轮实现引用、支援、天赋槽位；执行帧仅完成迁移设计。规则仍沿用 v6。

## 已实现

沿用变长 buffs 传输通道，每行从 12 扩至 16 字段。前 12 字段保持位置；
追加实体类别、源 counter SID、引用玩家、引用角色。类别为 buff / 支援 /
天赋槽 / 技能引用 / 卡牌引用。空引用保留源绑定，目标 hook 为 -1。

引用 counter 的动态值及 buff 数值只输出存在性，静态 min/max 为 0/1；
目标通过与动作共用的 canonical rule hook 表示。引擎存储仍是 typed reference，
不修改规则。支援公开位置和入场后经过回合数，天赋公开所属角色及规则引用。

网络按类别、所属方、角色、顺序及数值编码，与目标规则融合后做实体注意力。
源 SID 使用策略 counter encoder 的同一 embedding；费用 probe 共享该实体 encoder。
五范式复用现有变长采样/回放通道。旧 12 字段输入明确拒绝，旧权重不迁移。

技能引用是定义身份，不一定包含施放者。多个角色实例共用定义时，目标玩家/角色
为 -1，取最早 canonical hook 作为规则代表；只有唯一实例才输出实例位置。
这不是行为历史，不能推断上次实际施放者。

## 验收与边界

验收包括引用存在性、原始目标编号替换、hook 槽位重排、来源绑定、槽位占用、
视角、支援年龄、梯度、填充与无目标引用。编号替换测试验证动态引用不泄漏 raw ID；
不声称全量静态 IR 的任意重编号等变性。源 SID 仍为学习的槽位 embedding，
整个新规则集合的泛化仍须实测。

实体上限仍为 1024 行（包含规则展开后的 buff 行），溢出拒绝而非截断。
目前用所有实体池化得到状态向量；候选动作逐实体查询留待下一步。
暂停剩余程序和公开历史尚未补齐，因此仍不能宣称无记忆策略观测完备。

后续正式长训使用用户的局域网 5070 Ti 主机；本轮只做本机开发验收。
部署前确认机器身份及远端配置，重新生成数据和随机初始化权重。

## 下一轮优先核对：静态与动态 counter 视角

现有 BuildStaticObs 固定 P0 排列，BuildDynamicObs(perspective) 的 counter 区则
按己方优先排列，AgentBase 缓存静态 SID。新实体源 SID 使用真实 counter 的 SID。
因此还须对 P1、非对称队伍、强制换人决策做从引擎到五范式输入的成对核对，
确认调用链是否完成静态/动态视角对齐；不能以本轮实体自身的视角测试替代它。
在该项和暂停帧缺口关闭之前，不把 v7 称为完整可观测训练基线。
