# 暂停执行帧：路径清单与迁移设计

当前 continuation.go 保存根快照、边界操作、已选择分支，再重放到暂停点。
这保证分支模拟能继续，但 remaining program 不在 NN 观测中。

| 路径 | 当前依据 | 迁移要求 |
|---|---|---|
| 技能、卡牌或反应造成死亡，等待强制换人 | action_step / damage；continuation_branch_test | 保存伤害调用后的返回位置、事件上下文和未执行 hook |
| 卡牌选择目标 | PendingCardTarget；legacy_target_test | 保存卡牌规则引用、已支付状态和目标参数；只公开允许公开的信息 |
| 延迟伤害内再次死亡 | 玄冰.lua 的 defer_fn；deferred_input_resume_test | 将延迟闭包降为程序引用和显式捕获值；FIFO 队列保留 |
| 回合结束伤害等待换人 | deferred_input_resume_test、buff_round_order_test | 保留阶段、未结算实例序列、召唤物结束顺序与普通 buff 全局顺序 |
| 回合开始或准备技能内暂停 | boundaryNewRound / boundaryPreparing | 保留剩余阶段及准备技能位置，不重复已执行写入 |
| 原生 ExecuteEffect(fn) | boundaryEffect | 任意 Go 闭包不能自动序列化；提供显式原生 frame opcode，未迁移路径标为不支持完整观测 |

“准备技能字段”和“费用准备 hook”本身不等于暂停帧。星愿等通过 counter 驱动的
后续效果仍按 counter/buff 表达；仅在其执行中真正让出输入时创建 frame。

## 结构

每个 frame 保存：程序规则引用、指令位置、事件类型、执行方/目标、typed locals、
返回位置、阶段游标。独立记录待执行延迟队列及实例引用。引用用稳定程序/实体身份，
不保存函数指针作为可学习特征。模拟快照复制帧与队列，恢复时直接续执行。

NN 只投影公开帧和公开 locals；隐藏手牌、牌库顺序、随机状态不得因暂停而泄漏。
隐藏控制流不能原样公开，需要公开的决策摘要及历史模型；若摘要不充分，明确保留
部分可观测建模。绝不通过暴露根快照解决可学习性。

## 实施次序与验收

1. 给 IR 分配稳定程序引用和指令位置，列出所有可能让出输入的操作。
2. 先迁移伤害→强制换人与卡牌选目标；和现有重放路径做差分终态/事件序列验证。
3. 再迁移 defer、回合开始/结束、准备技能；验证两次连续死亡与跨分支恢复。
4. 对当前池可到达暂停边界输出 frame token；未支持 native closure 明确失败/标记能力限制。
5. 成对构造“棋盘相同、剩余程序不同”的状态，要求公开程序差异可见；
   “公开信息相同、隐藏信息不同”则要求观测一致。测试克隆、保存恢复、回放及 RNG 消耗一致。

本轮未替换 continuation 实现，后续不应仅追加一个 pending 标志就宣布完成。
