# C1 验证运行复盘

> C1 系列是 PPO→AZ 迁移后的首批真实训练运行，用于验证 IS-MCTS + 神经网络协同训练管线的可行性。

> **⚠️ 重要场景 caveat（2026-04-17 追加）**：C1v1-C1v4 **全部运行在
> 单角色 mirror match（赤蝶 vs 赤蝶）+ L1 only** 这个退化场景下。这是
> `training/config.py::smoke_config` 的默认 `team_0=team_1=["赤蝶"]`
> 配置，`c1_config` 未覆盖，`tools/launch_c1.py` 也未覆盖。因此：
>
> - 下文中所有"网络学到/没学到"、"d_model 够不够"、"价值头回音室"等归因
>   都是在**这个退化场景下**得到的，不能直接外推到多角色 / 多队伍组合
> - C1v1 的 "d_model=64 不够 → 网络价值作 leaf eval 失败" 的归因与
>   "单角色 mirror 场景太窄，网络容易 overfit" 两者**从未做过对照实验**
> - `docs/az/decisions.md D10` 声称的"领域随机化（每局随机阵容）"
>   **代码从未实现** — `ALL_CHARS` 常量存在但训练侧不引用，`GicgEnv`
>   阵容在构造期固定，`reset` 不换阵容
>
> C 阶段后续（G1 阵容随机化）完成后，需要复审下述归因并在本文档
> 追加对照数据。详见 `docs/az/generalization_review.md`。

## 背景

PPO 自对弈在 phase1b 持续回归后被放弃（见 `decisions.md`）。核心训练栈（B 阶段）完成后，C1 是第一个验证运行系列：确认网络能否通过自对弈 MCTS 数据学到有意义的策略和价值函数。

C1 系列包含四个子运行：

| 运行 | 目的 | 状态 |
|------|------|------|
| C1v1 | 纯网络叶评估 + 纯网络先验 | 失败 |
| C1v2 | 纯 rollout 叶评估 + 均匀先验（对照组） | 成功验证搜索引擎 |
| C1v3 | 固定混合（rollout 70% + 网络 30%） | 失败（无显著改善） |
| C1v4 | lambda 退火（0→0.8 over 1500 games） | 进行中 |

---

## C1v1：纯网络模式（失败）

### 配置

| 参数 | 值 |
|------|-----|
| d_model | 64 |
| n_rollouts | 400 |
| value_mix_lambda | 1.0（纯网络价值） |
| prior_mix_lambda | 1.0（纯网络先验） |
| n_workers | 4 |
| par | 4 |

### 结果

运行 2000 局，耗时 8.1 小时。

**Gauntlet 轨迹**（绝对胜率 vs 固定对手）：

| 检查点 | vs random | vs mcts_50 | vs mcts_200 |
|--------|-----------|------------|-------------|
| g500 | 0.80 | 0.10 | 0.05 |
| g1000 | 0.75 | 0.20 | 0.10 |
| g1500 | 0.75 | 0.15 | 0.00 |
| g2000 | 0.65 | 0.10 | 0.05 |

**Arena**：20 次评估中仅 7 次替换（35%），g300 后再无成功替换。

**损失**：v_loss 和 p_loss 在 Q3-Q4 均上升——网络在退化。

### 根因诊断

逐层拆解 MCTS 中网络各组件的贡献：

| 实验 | vs random 胜率 | 结论 |
|------|---------------|------|
| IS-MCTS + 随机初始化网络价值 | 20% | 网络价值比随机更差 |
| IS-MCTS + 随机 rollout 价值 | 90% | 搜索引擎本身正常 |
| 网络 + MCTS 100 vs 纯 mcts_50 | 0–25% | 网络先验有害 |
| 训练先验 + rollout vs 均匀先验 + rollout | 60% vs 80%（vs mcts_50）| 先验同样有害 |

**结论**：网络价值和先验均在自对弈回音室中训练，学到的模式仅对自身有效，无法泛化到真实对局。d_model=64 的网络容量不足以从 ±1 终局信号中学到有意义的中间局面价值。

---

## C1v2：纯 rollout 对照（成功验证）

### 配置

| 参数 | 值 |
|------|-----|
| d_model | 128 |
| n_rollouts | 200 |
| value_mix_lambda | 0.0（纯 rollout 价值） |
| prior_mix_lambda | 0.0（纯均匀先验） |
| entropy_coef | 0.01 |
| n_workers | 4 |
| par | 4 |

### 结果

运行 1097 局，约 3 小时（g1000 gauntlet 后终止）。

**Gauntlet 轨迹**：

| 检查点 | vs random | vs mcts_50 | vs mcts_200 |
|--------|-----------|------------|-------------|
| g500 | 0.95 | 0.40 | 0.50 |
| g1000 | 1.00 | 0.60 | 0.40 |

**Arena**：g100 替换成功（wr=1.0），后续所有 arena 均失败（wr 0.225–0.40）。

### 分析

lambda=0 意味着 MCTS 完全不使用网络输出——搜索强度恒定，不因网络改进而提升。这退化为**纯监督学习**：网络学习匹配 rollout-MCTS 的访问分布，但无法反过来改进搜索本身。

Arena 机制在此模式下无意义：冠军和挑战者使用完全相同的搜索（rollout + 均匀先验），网络不参与决策，所以 arena 对局本质上是两个相同的 rollout-MCTS 对弈，结果趋近 50%。

**价值**：C1v2 确认了搜索引擎和训练管线端到端正常工作，gauntlet 曲线清晰上升。

---

## C1v3：固定混合模式（失败）

### 配置

| 参数 | 值 |
|------|-----|
| d_model | 128 |
| n_rollouts | 200 |
| value_mix_lambda | 0.3（30% 网络 + 70% rollout） |
| prior_mix_lambda | 0.3（30% 网络 + 70% 均匀） |
| gauntlet_mcts_rollouts | (50, 100, 200) |

其余与 C1v2 相同。

### 结果

运行约 500 局后终止。

**Gauntlet**：与 C1v2 持平，vs mcts_200 约 50%。网络 30% 贡献没有带来可测量的改善。

**Arena**：win rate 从 0.325 升至 0.475，但始终未达到 0.55 替换阈值。整个训练过程 champion 从未被替换。

**吞吐量**：~148 局/小时（C1v2 的 44%）。

### 分析

固定 lambda=0.3 的问题：训练初期网络输出是噪声，30% 的噪声混入 leaf evaluation 和 prior 后轻微降低了搜索质量。这个噪声不足以形成正反馈循环——网络从略差的搜索数据中学习，学到的改善太微弱，无法跨过 arena 门槛。

**关键洞察**：lambda 需要动态调整。训练早期应当以 rollout 为主（网络不可信），随着网络改善逐步提高网络权重。这正是 AlphaGo 原始论文的做法——在 training 过程中退火 rollout-to-network 的混合比例。

## C1v4：Lambda 退火模式（进行中）

### 配置

| 参数 | 值 |
|------|-----|
| d_model | 128 |
| n_rollouts | 200 |
| lambda_anneal_games | 1500 |
| lambda_start | 0.0（纯 rollout + 均匀先验） |
| lambda_end | 0.8（80% 网络 + 20% rollout） |
| entropy_coef | 0.01 |
| checkpoint_every_n_games | 200 |
| games_per_arena | 100 |
| games_per_gauntlet | 500 |
| gauntlet_mcts_rollouts | (50, 100, 200) |
| n_games | 2000 |

### 设计思路

从 C1v2（lambda=0）的成功出发，用线性退火逐步引入网络贡献。前 ~375 局（lambda < 0.2）等价于 C1v2 的纯 rollout 模式，确保网络从高质量搜索数据中冷启动。之后网络权重线性增加，允许自我改进循环逐步建立。

### 早期观察（截至 g271，lambda=0.146）

**损失趋势**：

| 阶段 | v_loss | p_loss | entropy |
|------|--------|--------|---------|
| 早期（g0-20） | 1.30 | 5.48 | 2.02 |
| 中期（g100-130） | 0.03 | 1.51 | 1.51 |
| 最新（g250-270） | 0.05 | 1.54 | 1.55 |

v_loss 从 1.30 快速降至 0.03-0.05，说明 value head 在有效学习。p_loss 收敛至 ~1.5。

**Arena 进展**：

| Game | Win Rate | 结果 |
|------|----------|------|
| g100 | 97.5%（39-1） | 换章（vs 随机初始化） |
| g200 | 57.5%（23-17） | 换章（vs g100 champion） |

g200 arena 刚过 55% 门槛——两个版本强度接近，说明增量改进已非碾压式，而是渐进式。

**吞吐量**：~130 局/小时。

**Gauntlet**：未产出（eval_service 启动延迟，已修复）。g500 时将有首次 gauntlet 数据。

### 终止状态（2026-04-17 手动 kill at g1051）

C1v4 在 g1051 被手动 kill（场景退化原因，详见顶部 caveat），未跑完 g2000。

**Gauntlet 全程轨迹**：

| Game | vs random | vs mcts_50 | vs mcts_100 | vs mcts_200 |
|------|-----------|------------|-------------|-------------|
| 300  | 1.00      | 0.60       | —           | —           |
| 500  | 0.90      | 0.70       | 0.50        | 0.25        |
| 1000 | 0.95      | 0.50       | 0.50        | **0.45**    |

**单角色 mirror 场景下退火策略 work**：vs mcts_200 从 g300=10% →
g500=25% → g1000=45%，单调上升、跨过 mcts_50/mcts_100 持平线。
若继续跑到 g2000 lambda 饱和到 0.8，预计会突破 50%。

**但**：这是单角色 mirror 场景的训练强度，不能推断"网络学到了通用策略"。
Step D 阵容随机化重训前，C1v4 final 的"绝对强度数字"只在赤蝶 vs 赤蝶 + L1
这一点上有效。

### G3 扰动诊断（2026-04-17，使用 champion_g01000.pt）

`tools/probe_numeric_sensitivity.py` 在 c1 scenario 早期 obs 上做对照扰动：

| 扰动对象 | value 变化 | top1 prior 变化 | 结论 |
|---|---|---|---|
| static obs 中 hook 的 `TokLitNumber` value（扫 1-8） | **无变化** | **无变化** | hook channel 麻木 |
| static obs 中 hook 的 type token（enum/hook id swap） | **无变化** | **无变化** | hook channel 麻木 |
| dyn obs 中前 10 个 counter_values（±20 偏移） | **-0.99 → +0.97** | **idx 变 4→7→25** | 正常响应 |

**强阴性结论**：C1v4 训出的网络学到了"**忽略 hook channel，只看 counter values**"的
捷径。HookEncoder + CrossAttention 在前向时没贡献信号。

**根因**：单角色 mirror 训练下所有局看到的 hook 集都相同（赤蝶的几个技能 hook），
hook channel 携带的信息对区分局面**信息熵 = 0**。网络只能从 counter values
学到信号，hook 通路被自然 pruning。

**对 G2 的含义**：数值 token 编码改造（scalar sinusoidal 等）在当前训练制度下
完全没意义——hook 通路根本没被使用。**G2 暂不动**，等 G1 修复后重测。

**对 d_model=64 失败归因的含义**：C1v1 把"网络价值不准"归因为"d_model=64
容量不足"，但实际可能是"hook channel 在这种场景下天然无信息，网络容量再大
也学不到 hook→outcome 的映射"。归因仍待 G1 修复后用对照实验验证。

## 关键发现

### 1. 网络价值作为叶评估器是小模型 AZ 的关键失败点

d_model=64 的网络从 ±1 终局奖励学习中间局面价值，信号太稀疏、模型太小。随机初始化的网络价值甚至劣于随机 rollout（20% vs 90% 对 random）。

### 2. 随机 rollout 价值无偏且可用

随机 rollout 不依赖网络，提供无偏的局面价值估计。作为基线叶评估器，与 IS-MCTS 配合即可达到 90%+ vs random。

### 3. 固定混合比例不够——需要退火

C1v3（固定 lambda=0.3）证明简单地混入网络贡献不足以启动自我改进循环。训练初期网络是噪声源，固定比例无法适应网络质量的变化。AlphaGo 的退火策略（从纯 rollout 渐变到网络主导）才是正确方案。C1v4 采用此策略，早期迹象积极。

### 4. d_model=64 不足以泛化价值函数

C1v1（d_model=64）的网络价值完全失效。C1v2/v3/v4 升至 d_model=128。价值函数需要足够的表示容量来编码跨队伍、跨卡池的局面评估。

### 5. Arena 在 lambda=0 时无意义，退火模式下恢复

Arena 衡量"新网络是否比旧网络更好"。当 lambda=0 时网络不参与搜索决策，arena 退化为两个相同 rollout-MCTS 的随机对弈（C1v2 验证了此现象）。C1v4 的退火模式下 arena 恢复了正常功能：g100 和 g200 均成功换章。

### 6. 自对弈回音室

C1v1 的网络在封闭自对弈中训练，学到的模式仅在"对手也使用相同错误价值函数"时有效。面对外部对手（mcts_50、mcts_200）时表现劣于随机。退火策略通过在早期保留 rollout 基线来打破回音室。

### 7. 吞吐量对比

| 运行 | n_rollouts | 模式 | 吞吐量 |
|------|-----------|------|--------|
| C1v1 | 400 | 纯网络 | ~247 局/小时 |
| C1v2 | 200 | 纯 rollout | ~338 局/小时 |
| C1v3 | 200 | 固定混合(0.3) | ~148 局/小时 |
| C1v4 | 200 | 退火(0→0.8) | ~130 局/小时 |

退火模式早期（lambda 低）接近 rollout 速度，后期随网络介入会略慢。C1v3/v4 的降速主要来自网络先验导致的不均匀树展开。
