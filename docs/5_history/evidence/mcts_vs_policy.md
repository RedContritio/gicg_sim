# MCTS 对战训练策略——可行性探测

来源：`tools/mcts_vs_policy.py`（已提交 `d519b08`）

**待回答的问题**：基于搜索的 MCTS 是否真的比经过训练的最优策略产生更强的对局表现？如果是，架构迁移的合理性显而易见；如果否，则需要将价值网络作为先验。

## 实验配置

- **MCTS 一侧**：纯 UCT + 随机模拟（无任何学习组件）。每次决策 200 次模拟。最大模拟深度 80。均匀先验。
- **策略一侧**：`artifacts/202604141523_p0p1_minrew/phase0_1/phase1a/checkpoint.pt`（argmax 贪心）。这是在完整 PPO 栈下产生的最强检查点（B3 运行奖励归一化 + C 按规模池 ELO + 最简 3 系数奖励），经过 6 个成功通过的阶段和 210 轮 phase1a 训练（共约 1500 轮训练迭代）。
- **每场景对局数**：40 局，交替先后手以控制先手优势。
- **场景**：1v1 L1（纯填充牌），1v1 L1+L2（热身卡牌组），2v2 L1+L2（phase1b 出现停滞的场景）。

## 结果（2026-04-14）

| 场景 | MCTS 胜 | 策略胜 | 平局 | MCTS 胜率 | 秒/局 |
|---|---|---|---|---|---|
| 1v1 L1 | 38 | 2 | 0 | **95%** | 2.4 |
| 1v1 L1+L2 | 39 | 1 | 0 | **98%** | 3.6 |
| 2v2 L1+L2 | **40** | **0** | 0 | **100%** | 21.9 |

**汇总**：120 局中，MCTS **117** 胜，策略 **3** 胜，平局 **0**。
**MCTS 综合胜率 97.5%。**

## 解读

策略玩家并非在绝对意义上弱——它连续通过了 6 个 ELO 门控阶段，对手是过去版本的自身检查点。但面对任何基于搜索的对手，它都处于完全劣势：

1. **搜索在这里严格强于网络。** 使用随机模拟的纯 MCTS（零学习组件，每次决策 200 次模拟）在 120 局中对训练了约 1500 轮的网络胜率达 97.5%，这绝非微弱优势。

2. **2v2 场景被完全压制**——正是同一个 2v2 L1+L2 场景下，phase1b 在 PPO 训练中陷入持续回退。PPO 智能体根本无法在该场景中找到强力打法，而随机模拟 MCTS 则轻松找到了。

3. **差距随复杂度拉大。** 从 1v1 L1（95%）到 2v2 L1+L2（100%），随着场景变得更复杂，MCTS 的优势持续增大，表明在更丰富的游戏环境中 PPO 的训练效率比 MCTS 的搜索效率退化得更快。

4. **PPO 栈的"阶段跃迁"现象现在有了解释。** 我们反复观察到的 phase0c→d 崩溃、phase1a→b 回退、镜像→非镜像不稳定性，都是单智能体 PPO 无法维持稳定自对弈均衡的症状。MCTS 不存在这个问题，因为它每次决策时都从搜索中重新计算策略，而非依赖梯度更新的网络。

## 对设计的启示

- **基于搜索的方法是这款游戏的正确架构**。AlphaZero / IS-MCTS 是正确方向。
- **PPO 通过添加更多技巧无法拯救**——过去几天我们上线的约 5-10 项 PPO 时代改进（B3、C、最简奖励、新卡奖励等）都没有缩小这一差距。
- **网络的作用不是取代搜索，而是让搜索更快/更强**：AZ 训练的网络为 PUCT 提供策略先验，并为叶节点评估提供价值估计，两者都能减少每次决策所需的模拟次数。但即使没有网络，单靠搜索已经能赢。
- **AZ 的引导风险较低**：如果均匀先验 MCTS 已经能击败训练好的 PPO，那么即使是随机初始化的 AZ 网络，经过几千局 AZ 训练循环后，也应该能迅速超过这一基线。基础对局维度不存在组合发现危机。

## 注意事项

- MCTS 玩家使用的是 **PIMC（完全信息蒙特卡洛）**——在模拟过程中可以看到对手手牌，这是一种已知的乐观偏差（"透视"）。对阵同样使用透视的对手时偏差相互抵消，但 117-3 的结果是对战一个**无法**看到对手手牌的策略玩家，因此这是 MCTS（有透视）vs 策略（无透视）的比较，会在一定程度上高估 MCTS 的实力。
- 然而，IS-MCTS 设计（D2）消除了透视问题，而且 97.5% 的差距过大，不能仅凭此偏差来解释。
- MCTS 玩家同样使用的是随机模拟。使用网络价值评估的 MCTS（即 AZ 实际训练的方式）会**更强**而非更弱，因此当前基线是保守估计。

## 重现实验

```bash
.venv/bin/python -m tools.mcts_vs_policy \
  --ckpt artifacts/202604141523_p0p1_minrew/phase0_1/phase1a/checkpoint.pt \
  --scenario 1v1_L1 --rollouts 200 --games 40

.venv/bin/python -m tools.mcts_vs_policy \
  --ckpt ... --scenario 1v1_L12 --rollouts 200 --games 40

.venv/bin/python -m tools.mcts_vs_policy \
  --ckpt ... --scenario 2v2_L12 --rollouts 200 --games 40
```

每次运行输出逐局胜者、汇总胜率及耗时。
