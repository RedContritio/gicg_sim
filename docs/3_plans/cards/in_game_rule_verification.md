## 怎么记录

- 优先测试标有 **优先** 的条目；其余可在正常对局中顺便记录。需要批外角色/卡牌的场景另行搭建，不要求只用当前第一批牌组。
- 每次记录实际客户端版本、日期、模式、阵容和相关卡牌；尽量排除其他增伤、减费、治疗和行动顺序效果。
- 截图/录像应能看清前后血量、充能、骰子、附着、出战位置和相关状态次数。无法看到内部事件时，只写观察到的结果，不推断“没有触发某事件”。
- 同一条含多个子场景时分别填写。实际结论与当前处理不同，先保留双方记录，再修改规则和回归测试。
- 更新后只维护最新规则；旧实测作为历史证据留在该条，不能当作新版本验收。

状态：`待实测` / `已实测一致` / `已实测不一致` / `未能复现` / `版本更新待复测`。下面每条结果栏均待填写。

## 伤害、附着、反应与死亡

### B10 纯附着触发反应，不产生伤害【优先】
- 搭建：出战分别带火、冰、雷附着，等待芭芭拉歌声之环施加水；先记录水环治疗前后的血量。
- 当前决定：用户确认无基础伤害的附着不产生伤害相关事件或反应附加伤害；冻结等非伤害结果保留。
- 观察：是否仅治疗而无后续扣血、后台是否受感电影响、冻结是否生成。治疗与可能的扣血须分帧区分。
- 实测结果：待实测；版本/日期/证据：待填。

### B11 主伤害被完全吸收时的反应附加效果【优先】
- 搭建：带水或冰的敌方出战有足够护盾/减伤，以雷伤触发感电或超导，确保主目标不掉血。
- 当前决定：用户确认原本有伤害即正常结算反应增幅和附加伤害；主目标不掉血不取消后台穿透。
- 观察：盾实际消耗、后台各自扣血、能观察到的受伤后效果。不能只看主目标血量。
- 实测结果：待实测；版本/日期/证据：待填。

### B12 穿透与增伤、减伤、护盾、免伤【优先】
- 搭建：使用菲谢尔爆发或超导/感电；后台配莲花酥或能保护后台的效果；另在适合的场景测试出战所受穿透。
- 当前决定：穿透不受增伤、减伤、护盾或免伤影响，也不消耗它们；正常扣血并可致死。
- 观察：实际扣血是否为原始穿透值，防御效果次数是否保留；用随后普通伤害确认效果仍存在。
- 实测结果：待实测；版本/日期/证据：待填。

### B13 结晶护盾的上限、补充与保护范围

- 观察：盾层数是否2封顶、溢出是否延长/改变效果、后台伤害是否消耗该盾。

### B17 超载、击倒与后台目标【优先】
- 搭建：分别让超载①命中出战但不致死；②击倒出战；③通过连锁/附加元素伤害命中后台；④仅剩一名存活角色。
- 用户暂定规则（2026-09-14）：超载击倒出战时也自动切到下一名存活角色，等待游戏内实测。当前代码已按此修改；跳过倒下角色、末位绕回首位，最后一人倒下直接结束。后台超载不切换无关出战；普通非超载击倒仍保留玩家选人。
- 依据：[社区规则说明](https://wiki.biligame.com/ys/七圣召唤)与用户当前暂定选择一致，但仍不视作游戏实测。代码测试覆盖双席位、火雷双向、跳过倒下角色、绕回、单次切换事件、无多余选人请求、后台与普通击倒对照。
- 观察：自动切换方向、是否需要玩家选人、有无多切一次、后台超载是否影响当前出战；附带切换伤害与死亡/伤害后效果的先后。实现中致死自动切换在死亡回调完成，非致死在伤害延迟阶段，时机也需实测。
- 实测结果：待实测；版本/日期/证据：待填。
