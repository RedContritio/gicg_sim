2026-09-13。用户确认当前五个练习角色及L1–L6卡是简化教学环境，希望后续逐批接入仓库已有原生角色和卡牌。本文件是规划，不改变当前56主训练，也不表示原生内容已验证完成。

## 仓库事实与版本边界

本次实际清点：

- `data/raw` 与 `data/cleaned` 各有138条character、507条action、61条monster记录。action分为258装备、161事件、88支援；这是资料条目数，不是已经可训练或全部可携带的牌数。
- `data/pools/v_phase2` 有7个角色和7个行动牌Lua。角色是凯亚、凝光、砂糖、柯莱、坎蒂丝、克洛琳德、玛薇卡；行动牌是旅行剑、魔导绪论、甜甜花酿鸡、蒙德土豆饼、最好的伙伴、派蒙、鸣神大社。
- 该池有显式TODO：凯亚寒冰之棱、柯莱柯里安巴、凝光璇玑屏、砂糖强制切换/风灵变色，以及复杂角色资源机制。鸣神大社的奇数骰条件/次数语义也被简化。旧backlog写7角色6牌，与当前7牌不一致，不能照搬为最新清单。
- cleaned不是无误的规则规范，例如柯莱描述内仍有HTML残片。现有manifest也明确没有可靠的官方游戏版本字段。字段锁测试只能证明与cleaned一致，不能单独证明符合某个官方版本。

用户最新确认：**始终只支持最新官方正式服，不考虑过时版本**。新资料现在拉取，之后每次更新都做差异审核并升级当前实现；不提供旧版玩法维护。单次训练固定输入快照是为了实验可复现，不表示继续支持旧版。产品与论文目标见 `../pve_assistant_and_research.md`。

开发中的规则边界和歧义统一追加到 [游戏内规则核验清单](in_game_rule_verification.md)，包括用户已决定但仍准备实测的规则；代码测试与游戏实测分别记录。

已找到现有拉取链路：

- `tools/cards/fetch.py`：通过米游社百科的 `act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page` 拉详情，支持类型/ID/名称筛选、独立输出目录、重试和限流。
- `tools/cards/fetch_list.py`：通过同域 `common/blackboard/ys_obc/v1/home/content/list` 拉目录及费用辅助字段。
- 两者没有指定游戏版本的参数，抓的是接口当前内容；详情下载遇到同名已有文件直接跳过。因此不能原目录重跑后便声明已更新到某版本。
- `tools/cards/transform.py` 能清洗详情，但目录索引目前从固定 `data/raw_list` 读取；独立快照转换前需支持显式索引路径，避免新详情混用旧目录。

规则准备增加以下步骤：

1. 从官方发布/更新公告核实正式服版本及七圣召唤调整，记录证据链接；排除测试服和特殊玩法变体。
2. 用现有工具抓到全新的独立快照目录，同时保存详情与目录；记录抓取时间、来源URL、文件SHA、工具版本与完整性检查。抓取失败/空目录应令准备失败，不能只相信当前工具退出码（详情工具列表失败后会继续循环）。
3. 按同一快照清洗，输出相对旧资料的新增/修改/缺失和解析异常；缺失条目先审核，不自动当作官方删除。
4. 对即将接入的每批内容核对官方调整及依赖状态。百科可能滞后，不能仅凭官方域名证明所有条目一致属于目标版本；冲突保留证据、单独确认。
5. 保存已审核的原始快照与实现清单。官方更新后升级到最新资料和规则，并相应调整后续接入批次；不维护历史玩法分支。单次训练不热改环境，更新后的训练使用新的来源记录。

给每条内容记录来源ID、raw/cleaned摘要、目标规则版本、审核状态及依赖。项目发布号继续用vA.B.C；官方版本、数据快照ID和课程批次另列，不用vNN临时实验名混淆。2026-09-13已完成最新官方接口全量抓取，输出 `artifacts/official_latest_20260913/`：147角色、554行动、61魔物，共762条；下载零失败，目录与详情ID一致、无重复和空详情，逐文件SHA见manifest。相对旧资料角色新增9，行动新增48/缺失1；JSON差异不等同效果改动。接口抓取成功与逐条规则审核完成是不同状态。

## 总体策略

用户2026-09-14确定第一批为 **凯亚、迪卢克、芭芭拉、砂糖、菲谢尔五个角色一并接入**，覆盖其完整技能与关联效果，作为同一内容批次验收。后续批次默认2个角色＋6–8张行动牌；包含陌生资源机制时缩为1个角色＋4–6张相关牌。批次按机制依赖与覆盖组织，L1–L6学习难度作为辅助标签，不能假定原生角色都等价于某一教学级别。

新增的是完整可执行的内容包：角色技能、被动、关联状态/召唤物、生成牌及必要原语。未纳入牌池的天赋牌可以分批，但已纳入的卡不能保留影响玩法的TODO。缺机制则留在实验池，不以简化效果进入“原生已支持”清单。

保留三个明确区分的任务：

1. **教学基准**：当前五角色与自定义L1–L6，冻结成绩和权重。
2. **迁移实验**：小批原生内容与已验证教学内容混合，先做2v2；它只是控制变量的迁移任务，不宣称完整官方七圣召唤。
3. **原生基准**：只使用审核完成的原生内容，匹配目标版本的对战规则，逐步切到3v3。

当前教学环境的10回合裁决、跨双方buff排序、简化角色数和双方角色不重合约束，不能无条件继承成“官方规则”。原生规则配置需单独核对，双方阵容允许何种重复/镜像以目标规则为准；不要把课程采样限制当作构筑合法性。

## 每批固定流程

1. **规则准入**：逐条对照原始资料，列目标、费用、时机、次数、期限、归属、生成物；先补完整依赖再声明可用。
2. **环境验证**：独立预期的机制例子、边界与组合测试。覆盖死亡/强制切换、后台目标、减费叠加、回合末先后、召唤/支援满区、生成与弃置、克隆/恢复/reset，以及双席位一致性。不是只测“能加载”或把实现输出存成预期。
3. **NN信息检查**：所有决定合法动作或未来效果的公开状态与规则关联能被模型看到；原语不足则扩展原语或动态语义，不删掉原生效果迁就旧网络。隐藏手牌等仍不能泄漏到策略/搜索。
4. **冻结模型前测**：新内容在训练前用旧模型做一次适应前测，记录零样本基线。若观察schema不兼容，要先给出显式迁移方案，不能修改旧权重指纹假装兼容。
5. **迁移训练**：先提高新内容曝光率，再回到目标随机构筑分布；初始可约一半对局至少含一个新增角色，其余回放已审核的旧任务，比例按覆盖与遗忘证据调整。BC＋RL作为当前实用路线，纯RL长期支线独立标注。
6. **独立评估**：仅开发集选模；新种子终评包含旧内容回归、新内容专项、混合/纯原生任务、D1与D2，以及技能优先等较弱风格。旧测试集作为诊断使用过后，不再冒充新独立测试。
7. **收尾交付**：内容清单、来源/版本、规则与NN验证、模型SHA、配置与种子、逐卡覆盖/价值、代表性回放和下一批依赖。

每批预算由真实吞吐和学习曲线决定，不机械复制当前12轮。先小规模端到端验收，再在56采集/训练/评估；本机仅准备、轻量测试与报告。可以保留旧模型作回归，新增语义导致经验失配时重新采样，不复用失效回放。

## 升级与验收

**规则准入与策略晋级分开**：实现完整且验证通过即可进入“已审核内容”；模型暂时不会用不表示要把原生牌删回去。训练需要达到该阶段预注册的D1/D2与旧任务回归要求，才进入下一轮大规模扩展；探索性提前接入不得标为阶段已达标。

每批至少报告以下分布：新角色实际登场、每张新牌入组/进入手牌/合法机会/出牌、按队伍与先后手的强度、超时/击倒结局、布局及支付一致性。武器/天赋按合法阵容统计，不要求在非法队伍出现。

3v3之前需扩展当前固定2v2的场景生成、分层采样、网络输入容量与目标/支付空间检查。角色数增加后不穷举所有阵容组合；按元素组合、角色/卡牌覆盖及对手分层，固定抽样面板并保留长尾新种子测试。D2复杂度会增长，先测实际成本；若用节点上限，明确标为受限D2，不能悄悄替换原强标准。

里程碑验收继续使用多个独立训练种子与新场景聚类区间，保持“对D1稳定优势，对D2有优势”的目标。原生任务改变了角色、系统规则和对手难度，不能直接用教学池胜率作原生强度证据。

### 第一批训练与强度验收协议（2026-09-14，首次原生优化前记录）

以下为第一批五角色、23牌的执行协议，取代上文尚未实施时的数量与2v2过渡建议。实际采用`configs/dmc/native_starter.toml`的3v3、固定30张随机合法构筑；10种三人队伍形成55种无序配对（含镜像），评估覆盖全部配对。当前10回合裁决及待实测边界是项目实验条件，报告必须披露，不能将成绩直接推广到完整官方对局。

1. **预热**：全新随机权重，128局D2示范、1000次GPU更新作为首个预算；不复用教学池权重或经验。当前种子123000仅用于开发探索。预热效果需实测，不以模仿损失下降当作实力提升。
2. **冻结前测**：预热完成后，在开发种子93100、55场景×双方席位×2布局的面板分别对D1/D2评估（各220局）。保存模型SHA、逐局结局、超时裁决比例和按阵容/席位的结果；本面板之后均属于开发数据。
3. **RL试运行**：从预热模型出发，先4轮、每轮128局；固定D2开发面板选模。初始对手可用D1；若开发结果显示对D1已学会而D2停滞，再切换D2或混合对手，明确记录改动并重新开始相应实验。保留预热模型作为候选，不能只因迭代较新便晋级。依据实测吞吐、胜率及KL决定扩预算，不预设1000更新/4轮就足够。
4. **独立重复**：确定训练预算和算法后，用三个新的训练种子941000、951000、961000分别从随机权重完成预热和RL；各用独立开发种子941100、951100、961100。不能把同一预热权重派生的三个RL随机种子当作三个完全独立训练。
5. **最终验收**：三份模型仅由各自开发集选择并冻结SHA，然后使用此前未运行的测试种子941900、951900、961900。每份模型对D1、D2各550场景×2席位×2布局，即各2200局；55配对各10种随机场景。按场景聚类，席位/布局不当独立样本；报告95%区间。
6. **通过标准**：三个独立训练各自对D1得分至少60%，且95%聚类区间下界大于50%；对D2各自区间下界大于50%。同时披露逐阵容、先后手、击倒/裁决结局及布局差异，不能靠平均分掩盖非法动作、信息泄漏或环境错误。没有足够证据则继续训练/修复，不调低门槛。这里60%是本项目对“显著优于D1”增加的实际幅度要求，不是官方或通用行业标准。

测试结果若被用来选模或调参，对应种子随即转为开发数据；下一次正式验收须在训练前登记新测试种子。最终报告区分监督预热与RL的贡献，不能把BC＋RL标成纯RL。旧教学池`verify_curriculum.py`固定15配对/720场景，不适用于本协议，后续验收必须按本协议核对原始逐局结果。
