## 架构边界

- Lua 数据定义规则与牌表，Rust 是唯一规则执行器，Python 不复制游戏逻辑。
- 通用训练层只管理配置、运行生命周期、产物和评测。
- 模型、replay、loss 和 rollout 属于 DMC 算法内部。
- 环境进程只运行规则和对手搜索；学习方动作由中央模型使用最新参数推理。
- 所有完整配置位于 `configs/{train,eval,web}/`，不存在配置继承。
- 实验产物位于 `artifacts/<experiment_tag>/<时间戳>_<六位序号>/`。

## 独立评测

F1D2 评测使用种子 30000–30499，每个种子分别让候选模型先手和后手，共 1,000 局。

| 记录 | 设备 | 胜 | 负 | 平 | 截断 | 胜率 | 先手胜率 | 后手胜率 | 平均 M1 | 耗时 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 正式基准 | CUDA | 776 | 224 | 0 | 0 | 77.6% | 76.6% | 78.6% | 未记录 | 未记录 |
| M1 链路复评 | MPS | 788 | 212 | 0 | 0 | 78.8% | 79.0% | 78.6% | 9.024 | 271.50 秒 |

CUDA 正式记录位于 `eval_vs_f1d2.json`；MPS 复评位于
`eval_vs_f1d2_mps.json`。不同设备的浮点计算可能改变临界动作选择，
后续共享的 F1D2 随机流也会随对局长度变化，因此两次结果不要求逐局完全一致。

M1 是最直接的终局悬殊性指标：

```text
M1 = |双方剩余总生命之差| + |双方存活角色数之差|
```

M1 越大表示终局越悬殊；它不改变胜负判定或训练奖励。

报告以 `artifacts/<experiment_tag>/<run>/` 为单位。同一运行下针对不同对手或配置生成的
评测 JSON 在同一份报告中汇总；总评表内合并换边结果，另列 M1 分布。

每个种子交换双方先后手后形成一组，并按两局结果分为先手必胜、后手必胜、DMC 必胜和
F1D2 必胜。MPS 复评的 500 组中分别为 86、84、309、21 组，没有未归类结果。报告的
M1 分布使用 Q1、Q2、Q3 标记线，具体四分位数和均值在图表右下角陈列；当前三个
四分位数分别为 6、9、11，均值为 9.024。

## 设备结论

- MPS 在 macOS 的非沙箱主机进程中可用；受限执行环境可能报告不可用。
- 当前模型推理规模小，且 F1D2 搜索与对局推进占据主要耗时。MPS 1000 局实测为
  271.50 秒，先前未单独计时的 CPU 运行约为 192 秒。
- 小规模、串行 F1D2 评测默认使用 CPU。MPS 保留为显式配置覆盖，批量结构发生变化后
  再重新测量。
- 训练设备与 checkpoint 设备类型属于训练签名的一部分，不做静默兼容。
